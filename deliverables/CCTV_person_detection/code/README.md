# 사람 인식 및 H.265 스트리밍 코드

대상은 Luckfox Pico Zero + IMX415입니다. 영상 송출은 1920×1080으로 구성하고, NPU 추론은 별도 저해상도 프레임으로 수행합니다. 공식 예제의 NPU 전처리·후처리 방식을 참고하되 영상이 추론 완료를 기다리지 않도록 실행 흐름을 분리했습니다.

## 처리 흐름

```text
IMX415 → ISP/VI ┬→ VI0 1920×1080 NV12 → H.265 VENC → RTSP
               └→ AI VI 640×360 NV12 → BGR 복사 → 최신 프레임 1개 → NPU → 사람 로그
```

주 영상은 VI→VENC로 직접 바인딩합니다. 송출 스레드는 인코딩 결과를 받아 RTSP로 전달하며 모델 실행이나 AI 대기열 잠금을 사용하지 않습니다. AI 캡처는 별도 영상 복사본을 한 칸짜리 대기 공간에 넣습니다. 새 프레임이 오면 이전 대기 프레임을 교체하고, 추론 중인 복사본은 그대로 유지합니다. 추론은 잠금 밖에서 실행하므로 느린 추론 때문에 캡처가 대기하지 않습니다.

영상에 박스를 그리기 위해 CPU 전처리·추론을 거치는 경로는 사용하지 않습니다. **현재 사람 검출 결과는 로그로 출력하며 송출 영상에는 박스를 표시하지 않습니다.** 영상 표시가 필요하면 추론 완료를 기다리지 않는 별도 오버레이 구현이 필요합니다.

이 구조는 프로그램의 추론 대기를 영상 경로에서 제거합니다. ISP/NPU/인코더의 메모리 대역폭, CPU, 드라이버, Wi-Fi는 공유하므로 실제 영상 FPS가 떨어지지 않는다는 보장은 아닙니다.

## 설정과 옵션

| 항목 | 설정 |
|---|---|
| 송출 | VI0 1920×1080, NV12 입력, H.265/HEVC CBR 기본4096Kbps |
| AI 영상 | 기본 VI1 640×360 NV12 → BGR → 640×640 모델 입력 |
| 모델 전처리 | BGR, 검정 여백, 비율 유지 리사이즈 |
| GOP | 60, 실제60fps를 의미하지 않음 |
| -f | AI 프레임 선택 상한, 기본5회/초. 영상 송출 FPS나 센서 FPS를 제한하지 않음 |
| -b / -t | 비트레이트(Kbps) / 신뢰도 기준(기본0.5) |
| -I | AI용 VI 채널1 또는2 선택 |
| -D | 두 VI 채널과 NPU, VENC/RTSP 없이 주 VI를 회수하는 진단 모드 |
| -S | AI용 VI 하나와 NPU만 실행하는 진단 모드 |
| -P | 고정 사진 입력 비교. 선택한 모드의 카메라 동작 유지. -P 및 -S -P는 보드에서 timeout 확인 |
| -N -P | 카메라 미초기화, 작업 스레드·슬롯으로 고정 사진 반복. 최소 12회 성공 후 timeout 관측 |
| -N -M -P | 같은 컨텍스트·입출력 버퍼로 주 스레드에서 반복 추론. 새 비교 옵션 보드 시험 전 |
| -m / -a | 모델 경로 / IQ 디렉터리 |
| RTSP | rtsp://보드의현재WiFi주소:554/live/0 |

## AI 실패와 종료 정책

실행 중 rknn_run 또는 후처리 실패 시 `NPU DISABLED`를 출력하고 AI 작업만 중단합니다. 주 영상 스레드에는 종료 신호를 보내지 않으며 자동 재시도도 하지 않습니다. AI 캡처/변환 오류 역시 일반 모드에서는 이미 시작한 송출을 유지합니다. `VIDEO fps=... ai=disabled`로 이를 확인할 수 있습니다.

모델 로드/메모리 할당 또는 카메라 초기화 단계에서 실패하면 프로그램은 시작하지 못합니다. 영상 인코더·주 영상·RTSP 쪽 오류와 Ctrl+C는 전체 종료 사유입니다. 진단 모드는 송출이 없으므로 AI 실패 시 종료합니다. 공유 드라이버 장애가 영상까지 영향을 주는 경우는 코드의 오류 분리만으로 복구할 수 없습니다.

동기 rknn_run을 강제로 중단하지 않으므로 종료 시 이미 시작된 추론의 복귀나 드라이버 타임아웃을 기다릴 수 있습니다. AI 오류가 있었다면 사용자 종료 후에도 반환 코드는 실패를 나타냅니다.

## 예제와의 관계

- NPU 속성을 모두 조회한 뒤 입력/출력 메모리 할당·바인딩, 동기 추론을 수행합니다.
- 검정 letterbox·정수 절삭 크기·공통 배율, 엄격한 점수 초과 조건, +1 IoU, NMS 후 경계 제한/정수화를 유지합니다.
- VI→VENC 바인딩과 송출은 simple_vi_bind_venc_rtsp 예제의 HEVC 분기를 참고합니다.
- 두 VI·작업 분리·최신 프레임 한 칸·AI 오류 격리는 프로젝트용 구성입니다. 공식 YOLO 예제의 단일 순차 루프와는 다릅니다.
- 사람 전용 필터/최대128개/std::sort, NV12→BGR 명시, stride/모델 검사, 예외/RAII는 프로젝트 차이입니다. 원본과 모든 결과가 동일하다고 주장하지 않습니다.
- 카메라 앱을 자동 종료하지 않습니다. 다른 카메라 앱은 사용자가 먼저 종료해야 합니다.

## 빌드

### CMakeLists.txt, build.sh와 Makefile의 관계

이 프로젝트에서 직접 관리하는 빌드 설정은 `CMakeLists.txt`입니다. 어떤 소스를 컴파일하고 어떤 SDK 헤더·라이브러리를 연결할지 지정합니다. `build.sh`는 이 설정을 사용해 구성 → 컴파일·링크 → 결과물 설치를 순서대로 실행하는 보조 스크립트입니다.

Ubuntu에서 CMake의 `Unix Makefiles` 생성기를 사용하면 `build/Makefile`이 자동 생성됩니다. 생성기를 따로 지정하지 않으므로 환경에 따라 다른 빌드 도구가 선택될 수도 있습니다. `cmake --build`는 선택된 빌드 도구를 호출합니다. 자동 생성된 Makefile을 직접 수정하지 않고 `CMakeLists.txt`를 수정한 뒤 다시 구성합니다.

| 설정/단계 | 역할 |
|---|---|
| ARM 교차 컴파일러 | x86 VM에서 RV1106 보드용 ARM/uClibc 실행파일 생성 |
| `VENDOR_ROOT` | 외부 RKMPI 예제의 헤더와 보드용 라이브러리 경로 |
| OpenCV 탐색·이미지 IO 검사 | 색상 변환·크기 변경 및 사진 읽기/쓰기 지원 확인. 컴파일·링크 검사이며 보드 실행은 아님 |
| `person_inference` | `npu_model.cc`와 `person_decode.cc`를 묶은 공통 정적 라이브러리 |
| `cctv_person_image` | `image_main.cc`와 공통 라이브러리를 연결한 사진 검출 프로그램 |
| `cctv_person_npu` | `main.cc`와 공통 라이브러리, 카메라·인코더·AIQ·RTSP 라이브러리를 연결한 실시간 프로그램 |
| `cmake --build … --parallel 2` | 최대 2개 빌드 작업을 병렬 실행. 카메라나 추론 FPS 설정이 아님 |
| `install` | 생성한 실행파일과 모델을 프로젝트의 `dist`에 모음. 보드 전송은 하지 않음 |

`BUILD_STREAMING`과 `BUILD_IMAGE_TEST`는 각각 실시간 프로그램과 사진 프로그램을 만드는 옵션이며 기본값은 ON입니다. 사진 입출력 지원을 찾지 못하면 실시간 빌드가 활성화된 경우 사진 프로그램만 생략합니다. `BUILD_IMAGE_TEST`는 삭제된 `tests` 폴더를 참조하는 옵션이 아닙니다.

프로젝트 내부 빌드 입력은 `include`, `src`, `model`이며 외부 SDK는 별도로 필요합니다. 빌드 시 `build`와 `dist`가 생성됩니다. `dist`에는 생성된 실행파일과 `model/yolov5.rknn`을 설치하며 README·테스트·SDK 라이브러리는 복사하지 않습니다. 빌드 성공과 보드에서의 정상 실행은 별도로 확인해야 합니다.

### VM에서 빌드

code 폴더의 소스·include·model·CMakeLists.txt·build.sh를 VM 프로젝트 폴더에 함께 반영합니다. 새 include/latest_frame.h도 필요합니다.

```sh
export LUCKFOX_SDK_PATH=/home/student/luckfox-live/luckfox-pico
sh build.sh /home/student/RKMPI/luckfox_pico_rkmpi_example
```

### 사용자가 보드에서 확인할 실행 형식

```sh
# 사진 테스트: 현재 BGR 전처리 실행파일로 확인
./cctv_person_image model/yolov5.rknn person.jpg result.jpg 0.5

# 1080p H.265 송출 + 최대5회/초 AI 입력 선택
./cctv_person_npu -b 4096 -f 5 -t 0.5
```

`VIDEO fps`는 실제 VENC 패킷 회수율이며 센서 FPS나 종단 지연이 아닙니다. `PERSON detect_ms`는 전처리·추론·후처리 시간입니다. `result_age_ms`는 AI VI 프레임 획득 후 경과 시간이며 VLC 재생 지연은 포함하지 않습니다. 두 VI의 시야/크롭이 같다는 전제에서 box1080 좌표를 계산합니다.

추론이 느릴 때 확인할 항목은 VIDEO fps 유지 여부와 PERSON 결과 주기의 분리입니다. -f를 낮춰도 실제 영상 처리율은 같은지 비교할 수 있습니다. 자동 보드 전송·실행은 없습니다.

## 검증 상태

사진 추론은 BGR 입력으로 23~24개, 약 97.8~105.5ms에 성공했다. 통합 프로그램은 카메라 입력의 rknn_run 실패가 재현되지만 오류 후 VIDEO fps=15.0 ai=disabled가 유지된다. 이 값은 인코더 회수율이며 VLC 수신 완료의 증거는 아니다.

ai=enabled는 추론 성공을 뜻하지 않는다. 성공 여부는 PERSON 로그로 확인한다. 설계상의 송출 분리가 동작하더라도 코드 전체의 정상 동작을 보장하지 않는다. 상세 관측과 제한은 상위 STATUS.md를 참조한다.

기존 후처리·최신 프레임 슬롯의 호스트 검사는 통과했다. 사용자가 -P 소스를 ARM 빌드했고 -P 및 -S -P에서 timeout을 확인했다. -N도 보드 반복 실행 중 실패했다. 새 -M은 공통 처리 코드의 모의 모델 호스트 검사를 통과했으며 전체 ARM 빌드·보드 실행 전이다.

## 고정 사진 입력 비교

`-P person.jpg`는 카메라와 보조 VI를 가동하면서 NPU 입력만 사진으로 대체한다. 기존 사진 프로그램과 같은 이미지 IO 헤더를 CMake에서 연결한다. 이미지 IO가 없는 빌드에서는 일반 스트리밍은 유지하지만 -P 실행은 시작 오류로 종료한다.

로그의 source=fixed-image 및 box_image는 사진의 결과이며 실제 송출 영상의 검출 결과가 아니다. 사진 원본 크기를 유지해 NpuModel로 전달하고 모델 내부에서 letterbox한다. 상세 시험 방법은 상위 FIXED_IMAGE_TEST.md를 참조한다.

`-N -P person.jpg -f 5 -t 0.5`는 카메라를 초기화하지 않는 비교 모드다. 모델은 주 스레드에서 초기화하고 동일한 작업 스레드와 최신 프레임 슬롯으로 사진을 반복 추론한다. -D/-S와 함께 사용할 수 없으며 다른 카메라 프로세스는 사용자가 먼저 종료한다. 이 모드의 pts_us는 0이고 result_age_ms는 사진 선택 이후 경과 시간이다. completed는 성공한 추론의 누적 횟수다. NPU 오류 시 영상이 없는 진단 모드는 자동 종료하며, 일반 송출 모드의 영상 유지 정책은 그대로다.

-N에 -M을 추가하면 모델 초기화와 반복 추론을 모두 주 스레드에서 수행한다. 추론 작업 스레드를 만들지 않으며 같은 InferenceRunner.step과 슬롯을 쓴다. 상세 비교 절차와 타이밍 차이는 상위 THREAD_REPEAT_TEST.md를 참조한다.
