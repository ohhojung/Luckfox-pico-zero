# I2 적용 상태 — 2026-11-12

## 현재 설정

메인1920×1080 및 서브960×540 모두 H.265 목표20fps/GOP20입니다. 센서 요청 -F30은 기존 약20fps 출력 시험 조건을 유지하기 위한 값입니다. 30fps 병목 해결본이 아닙니다.

## 이번 통합

- BoardServer 46703b3의 streamer를 검토하고 양쪽 프레임 상태 기록,5초 정지 감지,내부 재초기화(최초 포함3회),단계별 타임아웃,로그 용량 제한을 구현했습니다.
- 사용자 보드:3864×2192 SGBRG10; rkipc 종료 확인. 작은 센서모드로 변경하지 않습니다.
- RkLunch의 post_chk가 백그라운드로 실행됨을 확인했습니다. 기존 초기화 완료 지점에서 S59cctv로 시작을 넘기도록 배포 스크립트를 준비했습니다.
- heartbeat는 .100:3000,MAC wlan0,송신 및 상태 wg0,카메라 cctv-dual-rtsp를 기본값으로 사용합니다. 별도 필수 설정 파일은 없습니다.
- 설치 전 파일 백업 및 복구 스크립트, SHA256 검증, 한 줄씩 실행할 안내를 ../i2_board/README.md에 제공합니다.

## 검증과 한계

스트리밍 ARM 교차 빌드는 통과했습니다. QEMU 실행은 vendor 라이브러리의 Rockchip 장치 탐색 단계에서 SIGSEGV로 끝났습니다(보드 efuse/device-tree 없음). 에뮬레이터 스트리밍 실행 성공으로 보고하지 않습니다. 보드의 기존 AIQ 라이브러리는 교체하지 않습니다.

native heartbeat 실제 HTTP 클라이언트의 dry-run 무전송,403→200 재시도,JSON 필드,지정 인터페이스 부재 시 우회 금지를 검증했습니다. 상태 검사의 정상·오래된 프레임·한쪽 빈 프레임·PID 불일치·복구 중·손상 데이터와 셸 문법/OEM 패치 인식 검사를 통과했습니다.

보드의 양쪽 실측20fps·동시 재생·재부팅 자동 시작·장시간 복구·실서버 heartbeat·MediaMTX 재연결은 미검증입니다. READY나 프로세스 생존만으로 영상 성공으로 판단하지 않습니다. 최종 ARM heartbeat와 패키지 검증 결과는 배포 패키지 BUILD.txt 및 작업 기록을 확인합니다.


## 2026-11-13 보드 시험: 미해결 장애

사용자가 영구 설치 후 S59cctv running, health의 양쪽 최근 프레임, S60heartbeat running을 보고했습니다. 재부팅 직후 명령 실행 여부는 설치 대화 흐름에 따른 보고이며 독립 재검증하지 않았습니다. heartbeat 실행은 실서버 HTTP200을 입증하지 않습니다.

모듈화 버전에서 양쪽 약19.5~19.8fps 로그와 프레임 카운터 증가를 확인했습니다. VPN으로 live/1을 받는 VLC에서 demux 데이터·디코딩·표시 카운터가 증가했지만 사용자는 화면 정지를 보고했습니다. 영상 내용이 실제로 갱신되는지는 미확인입니다.

이후 state=failed, attempt=3, cctv stopped 확인. 로그에 NO_FRAME과 재시도, 커널에 rkisp_stream_stop 및 rkisp_isp_sd_s_stream timeout이 반복됩니다. 재초기화 후 영상 복구 실패는 확인됐고, 최초 원인은 미확정입니다. VLC 종료나 VPN을 원인으로 단정하지 않습니다. 종료 이후 WireGuard handshake 응답도 기록됐습니다.

다음 시험: 실패 로그를 보관하고 재부팅 후 VLC 미접속 상태에서 프레임·health 유지 확인, 이어 접속/종료 전후 비교. 해당 시험 결과는 아직 수신하지 않았습니다. 이 커밋은 개발 진행 상태이며 안정화 완료본이 아닙니다.
