## 점검 방법

새 패키지 `packages/i2-board-20261114-review/`를 보드에 전송한 뒤 폴더 안에서 실행한다.

```sh
sh check-board.sh wg0
```

서비스 프로세스·최근 프레임·rkipc 경쟁 여부·핸드셰이크 나이·서버 경로·UTC를 읽는다.
설정 변경이나 서비스 재시작은 하지 않는다. 키·Endpoint·전체 설정은 출력하지 않는다.
라우팅 출력에 LAN 주소가 포함될 수 있다. 출력 경로가 wg0인지 직접 확인한다.
오래된 핸드셰이크만으로 서버 중단을 단정하지 않는다. 실제 트래픽과 서버 상태를 함께 확인한다.
프로세스 실행은 HTTP200을 의미하지 않으며, 서버 수신은 웹 재생을 의미하지 않는다.

서버에서 보드 peer의 /32 AllowedIPs, MediaMTX의 TCP source 및 sourceOnDemand를 따로 확인한다.
메인 상시 수신 여부는 서버 설정에서 검증한다. 5초 수신 성공만으로 상시 수신을 입증하지 않는다.
반복 부팅·15분 이상 재생·VLC 재접속·VPN 양쪽 영상·웹 복귀는 별도 시험으로 기록한다.

## 우리 보드의 현재 미완료 사항

기존/진단 프로그램 및 서비스 정상 재생을 사용자가 확인했으나 앞선 정지 원인은 미확정이다.
새 codec 패키지 dry-run은 통과했다. rollback 안내 후 실제 재설치 완료는 확인되지 않았다.
마지막 ps에는 rkipc/cctv 모두 없었다. VPN의 잘못 붙은 PersistentKeepalive 수정 후 복구 결과도 미수신이다.
팀장님 보드의 통과 결과를 우리 보드의 통과 결과로 대신하지 않는다.
새 점검 스크립트는 로컬 셸 구문 검증 대상이며 실제 보드 검증은 별도로 진행한다.
